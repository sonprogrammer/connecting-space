# 관리자 재무 요약 대시보드 화면 제안

## 상태

- 이슈: #37
- 작성일: 2026-10-26
- 상태: 승인됨
- 기준: `main`의 #98 `GET /api/admin/financial-summary` 계약 및 2026-10-08 관리자 UX 명세

## 목적과 제안

관리자가 현재 처리할 업무를 놓치지 않으면서 프로젝트 재무 현황을 빠르게 확인하도록 한다. 오늘 할 일 업무함을 첫 번째 정보 계층으로 유지하고, 재무 요약과 최근 문의·프로젝트 일정을 보조 정보로 배치한다.

## 화면 구성

1. 기존 `오늘 할 일` 제목, 미처리 업무 종류별 건수, 우선순위 목록을 유지한다.
2. 업무 종류별 건수 바로 아래에 `프로젝트 재무 현황`을 둔다.
   - 범위 선택: 기본 `진행 범위` (`active`; 기획·제작 중·검수·보류 포함), 개별 프로젝트 상태, `전체`.
   - 카드: 예정 매출, 확정 매출, 입금 완료, 미수금.
   - 카드 하단: 집계 프로젝트 수, `asOf` 기준 시각, `/admin/projects` 이동 링크.
3. 기존 우선 확인 업무 목록을 유지한다.
4. 페이지 하단에 `최근 문의`와 `예정 출시일순 프로젝트` 미리보기를 나란히 둔다.
   - 문의 미리보기는 최근 5건을 제안하며 행 선택 시 `/admin/inquiries#inquiry-{id}`로 이동한다.
   - 프로젝트 미리보기는 현재 프로젝트 목록 API의 상태 필터와 `expected_launch_date` 정렬을 사용한다. 행 선택은 `/admin/projects?project={id}`로 연결해 선택한 상세를 열고, 전체 보기는 `/admin/projects`로 연결한다.

금액 카드와 문의·프로젝트 미리보기는 별도 업무 메뉴를 대체하지 않는다. 차트나 임의 운영 데이터는 추가하지 않는다.

## 데이터와 상태

- 재무 요약: `GET /api/admin/financial-summary?status=<status>`의 서버 계산값을 그대로 표시한다. 금액은 프론트에서 다시 계산하지 않는다.
- API 기본 `active` 범위는 `planning`, `in_progress`, `review`, `paused`를 포함한다. UI는 `진행 범위`로 표시하고 포함 상태를 함께 알려준다. `all`은 완료·취소 상태도 포함한다.
- `asOf`는 한 DB statement의 기준 시각이며 이후 요청에 재사용하는 snapshot 토큰은 아니다.
- 로딩: 재무 카드 스켈레톤과 문의/프로젝트 목록 로딩 상태.
- 빈 결과: `projectCount = 0`이면 금액을 0으로 표시하고 대상 프로젝트 없음 문구를 제공한다. 보조 목록은 각각 독립된 빈 상태를 표시한다.
- 오류: 최초 조회 실패는 재시도 가능한 오류 상태, 캐시가 있으면 기존 결과와 갱신 실패 안내를 함께 표시한다.
- 401/403은 기존 관리자 로그인 흐름으로 보낸다. 안전한 오류 메시지 외에 서버 상세 오류는 노출하지 않는다.
- 상태별 요약 query key를 분리하고 `cache: "no-store"`를 유지한다. 결제 변경 및 집계 범위에 영향을 주는 프로젝트 상태 변경 후 재무 요약 캐시를 무효화한다.

## 반응형과 접근성

- 데스크톱(1280px 이상): 재무 카드 4열, 최근 문의와 프로젝트 미리보기 2열.
- 태블릿(768px): 재무 카드 2열, 보조 목록 2열 또는 폭이 부족할 때 세로 배치.
- 모바일(360px): 재무 카드는 2열, 매우 좁은 폭에서는 1열. 문의·프로젝트는 핵심 정보만 담은 카드로 세로 배치한다.
- 가로 스크롤 없이 기존 테마 토큰, 보이는 포커스, 의미 있는 제목·레이블·상태 문구를 사용한다.

## 고려한 접근

- 선택: 현재 `/admin`의 오늘 할 일 흐름 아래에 재무 요약과 보조 미리보기를 추가한다. 이슈 #37 요구를 충족하면서 승인된 UX 명세의 업무 우선순위를 유지한다.
- 재무 대시보드를 별도 페이지로 둔다: 첫 화면에서 재무 상태를 빠르게 파악하려는 이슈 목표와 맞지 않아 선택하지 않는다.
- KPI·차트를 화면 최상단에 두고 업무함을 아래로 내린다: UX 명세의 오늘 할 일 우선 원칙과 충돌하므로 선택하지 않는다.

## 미확정 사항

- 이슈의 `마감 임박` 날짜 기준과 대상 상태는 API/UX에서 정의되지 않았다. 제안에서는 임의의 임박 기간을 만들지 않고 `예정 출시일순 프로젝트`라고 표기한다. 실제 기간 기준이 필요하면 별도 합의가 필요하다.
- 문의 미리보기 5건은 화면 제안상의 기본값이며 필요 시 조정 가능하다.
- 운영 DB의 #98 migration은 별도 승인 대상이며 프론트 작업에서 적용하지 않는다.
