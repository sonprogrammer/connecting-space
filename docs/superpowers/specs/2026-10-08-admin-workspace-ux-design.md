# 관리자 업무 공간 UI/UX 재설계 명세

## 문서 상태

- 작성일: 2026-10-08
- 상태: 대화형 설계 승인 완료, 문서 검토 대기
- 대상: Connecting Space 관리자 화면
- 기존안: `2026-10-06-admin-dashboard-redesign-design.md`를 대체한다.
- 범위: 업무 파악과 처리 흐름을 중심으로 정보 구조, 목록, 상세 진입 방식을 다시 설계한다.

## 배경

관리자 화면에 기능이 여러 곳에 분산되어 있고, 페이지가 길어 지금 무엇을 해야 하는지 또는 각 메뉴에서 무엇을 할 수 있는지 파악하기 어렵다. 사용자는 관리 기능을 외우지 않아도 첫 화면에서 전체 할 일의 수와 종류를 확인하고, 필요한 업무로 곧바로 이동하기를 원한다.

## 설계 목표

- 첫 화면에서 지금 처리해야 할 업무의 전체 수와 업무 종류별 수를 빠르게 파악한다.
- 업무를 우선순위와 대기 기간에 맞춰 확인하고 다음 행동을 시작한다.
- 문의, 견적, 프로젝트, 입금, 사이트 콘텐츠를 독립된 메뉴와 페이지에서 찾는다.
- 긴 정보를 목록에 펼치지 않고 모달 또는 정돈된 상세 페이지에서 처리한다.
- 화면 폭이 달라도 같은 업무 흐름을 유지하고 가로 스크롤 없이 사용할 수 있다.
- 사용자가 기능 구조를 기억하지 않아도 메뉴 이름과 다음 행동이 분명하게 보인다.

## 사용자가 승인한 핵심 결정

- 관리자 첫 화면은 지표·차트 중심 대시보드가 아니라 `오늘 할 일` 업무함이다.
- 업무함 상단에 행동 종류별 건수를 표시하고, 아래에 해야 할 일 전체를 우선순위 순으로 표시한다.
- 업무 상세는 빠른 확인용 모달과 긴 작업용 상세 페이지를 함께 사용한다.
- 문의 상세 페이지는 전체 진행 흐름과 현재 할 일을 함께 보여준다.
- 목록은 넓은 화면에서 표, 좁은 화면에서 핵심 정보 중심 카드로 표시한다.
- 모든 목록의 사용자는 `최신순`과 `오래 기다린순`으로 정렬을 바꿀 수 있다.
- 기본 정렬은 오늘 할 일에서 `오래 기다린순`, 각 업무 메뉴에서 `최신순`이다.
- 기존 녹색 계열과 시스템·라이트·다크 테마 방향은 유지하고 정보 구조와 화면 계층을 정리한다.

## 정보 구조와 메뉴

| 메뉴 | 목적 | 주요 콘텐츠 |
| --- | --- | --- |
| 오늘 할 일 | 모든 미완료 행동과 우선순위 파악 | 업무별 건수, 우선순위 업무 목록 |
| 문의 | 신규 문의 확인과 첫 답변 | 문의 목록, 빠른 요약 모달, 문의 상세 |
| 견적 | 견적 작성·발송·승인 상태 확인 | 견적 목록, 만료 견적 보관/필터 |
| 프로젝트·고객 | 승인 후 생성된 고객과 프로젝트 관리 | 프로젝트 목록, 고객 연결 정보, 프로젝트 상세 |
| 입금 | 예정·연체·완료 입금 확인 | 입금 목록, 입금 상세와 기록 |
| 사이트 관리 | 공개 사이트 콘텐츠 관리 | 포트폴리오, 서비스, FAQ |

메뉴 이름은 업무 용어로 표시한다. `문의·견적`, `고객·프로젝트·입금`처럼 서로 다른 처리 목적을 하나의 메뉴 이름에 몰아넣지 않는다. 사이트 관리 내부의 포트폴리오, 서비스, FAQ는 하위 메뉴 또는 탭으로 둔다.

## 오늘 할 일 화면

### 상단 업무 건수

네 종류의 행동 건수를 같은 시각적 우선순위로 확인할 수 있게 한다.

1. 신규 문의 답변
2. 견적 작성·발송
3. 승인된 견적의 프로젝트 전환
4. 연체 입금 확인

업무별 수는 전체 개체 수가 아니라 손 대표님이 처리해야 할 수다. 전체 처리 건수도 상단에 제공하고, 업무별 건수를 선택하면 해당 메뉴의 필터된 목록으로 이동한다. 진행 중 프로젝트 수처럼 참고 정보인 값은 처리 건수에 합산하지 않는다.

### 업무 목록

- 모든 처리 대상은 하나의 업무 목록에 모은다.
- 업무 그룹의 기본 순서는 연체 입금, 신규 문의, 승인 후 프로젝트 전환, 견적 작성·발송이다.
- 같은 그룹 안에서는 오래 기다린 항목부터 표시한다. 연체 입금은 연체 기간이 긴 순, 신규 문의와 견적은 접수·생성 후 대기 기간이 긴 순으로 한다.
- 각 항목에는 고객 또는 프로젝트 이름, 처리 종류, 기다린 기간 또는 연체 기간, 현재 상태, 다음 행동을 짧게 표시한다.
- 한 행에는 대표 행동 하나만 강조한다. 예: `문의 확인`, `견적 작성`, `프로젝트로 전환`, `입금 기록 확인`.
- 고객 문의 원문이나 긴 편집 폼을 목록 안에 표시하지 않는다.
- 사용자는 전체 업무함과 업무 종류별 필터를 전환할 수 있다.
- 완료·취소된 항목은 업무함에서 제외하고 해당 메뉴에서 이력으로 확인한다.

### 메뉴별 정렬

- `최신순`: 최근 접수·생성된 항목 우선.
- `오래 기다린순`: 접수·생성 후 대기 기간이 긴 항목 우선. 입금은 기한 경과 기간을 사용한다.
- 정렬 변경은 현재 목록 내에서만 적용하며 검색·상태 필터와 함께 사용할 수 있다.
- 정렬 옵션과 현재 선택은 텍스트로 표시하고 색만으로 표현하지 않는다.

## 상세 정보 열기와 처리

### 빠른 확인 모달

- 목록의 항목을 선택하면 짧은 요약, 현재 상태, 접수·기한 정보, 다음 행동을 모달에서 확인한다.
- 모달은 긴 원문 편집, 답변 작성, 견적 편집 또는 입금 입력을 담지 않는다.
- `상세 페이지에서 계속` 행동으로 해당 항목의 독립 URL로 이동한다.
- 모달은 Escape 및 닫기 버튼으로 닫히고, 닫힌 뒤 원래 목록 항목으로 포커스를 돌려준다.

### 상세 페이지

- 브레드크럼, 제목, 고객/프로젝트, 상태, 접수·기한 정보를 상단 요약에 둔다.
- 목록에서 돌아갈 수 있는 명확한 경로를 제공한다.
- 한 페이지에 긴 폼과 모든 업무 기능을 연속으로 펼치지 않는다.
- 현재 처리할 작업을 가장 눈에 띄는 카드나 영역으로 표시한다.
- 부가 정보와 완료된 단계는 접거나 별도 구역으로 둔다.

### 문의 상세의 진행 흐름

문의 상세 상단에 아래 진행 상태를 보인다.

`문의 → 견적 → 승인 → 프로젝트`

- 현재 단계와 현재 해야 할 일을 함께 강조한다.
- 문의 원문, 답변 초안, 견적/승인, 프로젝트 전환을 한눈에 찾을 수 있게 구획한다.
- 현재 작업만 편집 가능 상태로 전면에 표시하고, 관련 없는 긴 작업은 목록·요약 상태로 둔다.
- 승인 완료는 프로젝트 전환의 다음 행동으로 연결한다.
- 프로젝트 전환 후 관련 업무는 프로젝트 상세로 이어진다.
- 견적 만료 항목은 별도 상태 필터/보관 영역에서 확인할 수 있지만, 사용자가 승인한 네 가지 기본 오늘 업무에 임의로 추가하지 않는다.

## 목록 화면

### 넓은 화면

- 문의·견적·프로젝트·입금은 행 단위 표로 표시해 한 화면에서 여러 항목을 비교한다.
- 열은 각 메뉴의 핵심 정보만 선택한다. 긴 설명, 원문, 전체 고객 정보는 표에 넣지 않는다.
- 검색, 상태 필터, 정렬을 목록 제목 가까이에 배치한다.
- 표 행 선택으로 요약 모달을 열고 상세 페이지 링크를 제공한다.
- 목록은 페이지네이션 또는 명확한 더 보기 방식으로 관리한다.

### 모바일과 좁은 화면

- 표를 그대로 축소하거나 가로 스크롤에 의존하지 않는다.
- 표의 주요 열을 제목, 상태, 대기/기한 정보로 재구성한 카드 목록을 제공한다.
- 보조 정보를 카드 안에 모두 늘어놓지 않고 요약 모달과 상세 페이지로 보낸다.
- 검색·필터·정렬은 작은 화면에서도 한 손으로 접근할 수 있게 제공한다.

## 반응형 동작

### 데스크톱: 1280px 이상

- 고정된 전체 관리자 내비게이션을 사용한다.
- 업무 건수는 한 줄 카드 또는 동등한 밀도의 요약으로 표시한다.
- 업무 목록은 밀도 있는 표를 사용한다.
- 항목의 빠른 확인은 모달, 긴 업무는 상세 URL로 이동한다.

### 태블릿: 768px 이상 1280px 미만

- 내비게이션은 축소형 레일 또는 접이식 메뉴를 사용한다.
- 업무 건수는 두 열로 배치한다.
- 표는 핵심 열만 유지하고, 폭이 부족하면 카드 표현으로 전환한다.

### 모바일: 360px 이상 768px 미만

- 상단 헤더와 메뉴 서랍을 사용한다.
- 업무 건수는 두 열 카드로 표시한다. 더 좁은 화면에서 1열 전환을 허용한다.
- 업무 목록은 요약 카드로 표시한다.
- 모달은 읽고 조작할 수 있도록 화면 전체 대화상자 또는 상세 페이지로 표시한다.
- 문의·견적 편집처럼 긴 작업은 상세 페이지를 사용한다.

## 시각 스타일과 접근성

- 기존에 승인한 중립 배경, 흰/저채도 카드, 브랜드 녹색 강조색을 유지한다.
- 시스템·라이트·다크 테마 선택을 유지한다.
- 장식보다 간격, 제목, 상태, 다음 행동의 계층으로 화면을 구분한다.
- 상태는 텍스트와 아이콘을 함께 사용하며 색만으로 의미를 전달하지 않는다.
- 현재 메뉴, 정렬 상태, 필터 상태를 접근 가능한 이름과 상태 속성으로 전달한다.
- 키보드 포커스를 분명히 보이고 모달의 포커스 진입·순환·복귀를 지원한다.
- 좁은 화면과 확대 환경에서 내용이 잘리거나 가로 스크롤이 생기지 않게 한다.

## 데이터와 구현 경계

- 이 문서는 UI/UX의 정보 구조와 동작을 정한다. 세부 API 필드나 신규 데이터 저장 구조는 정하지 않는다.
- 업무 종류별 정확한 count와 전체 우선순위 목록을 제공하는 백엔드 계약은 구현 전에 현재 API를 조사해 결정한다.
- 프론트엔드는 상태 정의나 금액·기한을 임의로 재계산하지 않는다.
- 기능이 아직 제공하지 않는 데이터는 임의 값으로 보충하지 않는다. 사용할 수 없는 요약은 명확한 상태로 안내한다.
- 운영 DB, migration, 배포, 실제 고객 데이터 수정은 이 설계 범위 밖이다.

## 비목표

- 새로운 CRM, 프로젝트 방법론, 캘린더, 알림 채널을 추가하지 않는다.
- 첫 화면에 매출 차트나 일반 사업 지표를 필수로 넣지 않는다.
- 상세 화면에 모든 기존 기능을 한 번에 재배치하지 않는다.
- 사용자 확인 없이 목록 상태, 자동 우선순위, 만료 정책을 바꾸지 않는다.

## 수용 기준

- 첫 화면에서 전체 미완료 업무 수와 네 종류별 수를 확인할 수 있다.
- 한 화면에서 전체 업무 목록을 훑고 각 행의 다음 행동을 이해할 수 있다.
- 업무 건수 선택으로 관련 메뉴의 필터된 목록에 도달한다.
- 오늘 할 일과 메뉴별 목록의 기본 정렬이 명세와 일치하며 사용자가 두 정렬을 바꿀 수 있다.
- 목록 항목은 요약 모달과 상세 페이지로 이어진다.
- 문의 상세에서 진행 단계와 현재 처리할 일을 쉽게 찾을 수 있다.
- 데스크톱 표와 모바일 카드 사이에 정보 손실이나 가로 스크롤이 없다.
- 360px, 768px, 1280px에서 메뉴, 목록, 상세 작업이 사용 가능하다.
- 빈 목록, 로딩, 오류, 재시도, 만료 견적 상태를 혼동 없이 표현한다.
- 기존 light/dark/system 테마에서 상태와 포커스가 읽힌다.

## 아직 구현 전에 확인할 항목

- 문의·견적·프로젝트·입금별 표의 구체적인 열과 검색 조건
- 업무함 목록에서 한 번에 표시할 행 수와 추가 항목 탐색 방식
- 액션을 완료한 직후 다음 항목으로 자동 이동할지 여부
- 요약 데이터에 필요한 API와 서버 집계 경계

이 항목들은 시각 디자인을 구현하기 전에 현재 기능과 저장소 계약을 확인해 최소 범위로 정한다.
